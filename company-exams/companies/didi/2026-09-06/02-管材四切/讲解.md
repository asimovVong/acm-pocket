## 原始完整题目

以下按微信原文转录，保留原变量 m、约束和全部样例；仅统一公式、空格与数字排版。来源：[滴滴9月6日机考笔试真题与解析](https://mp.weixin.qq.com/s/lxkbH776rnz3PgnzkNKE4w)。后面的题意、输入输出与范围解释为学习讲解。

### 题目内容

车间里有一根已经按节编号的管材，共 m 节，从左到右第 i 节的价值是 v<sub>i</sub>。现在要在节与节之间切三刀，分成四段非空连续管，交给四个工班。一段的价值等于它包含的各节价值之和。

工班希望尽量均分：四段价值里的最大值减最小值要尽可能小。请算出这个最小差值。

约束：

- 4 ≤ m ≤ 100000
- 1 ≤ v<sub>i</sub> ≤ 1000000000

### 输入描述

第一行一个整数 m（4 ≤ m ≤ 100000），表示节数。

第二行 m 个整数 v<sub>1</sub>, v<sub>2</sub>, …, v<sub>m</sub>（1 ≤ v<sub>i</sub> ≤ 1000000000），表示各节价值。

### 输出描述

输出一个整数，即四段价值最大值与最小值之差的最小可能值。

### 样例1

**输入**

```text
5
4 5 1 2 8
```

**输出**

```text
5
```

**说明**

切成 [4]、[5]、[1,2]、[8]，四段价值为 4、5、3、8，最大减最小为 5。这是最小可能差值。

### 样例2

**输入**

```text
4
1 1 1 1
```

**输出**

```text
0
```

**说明**

只有一种切法，四段都是 1，差值为 0。

### 样例3

**输入**

```text
5
9 1 1 1 1
```

**输出**

```text
8
```

**说明**

左边一节特别大。一种切法是 [9]、[1]、[1]、[1,1]，价值 9、1、1、2，差值为 8。其它切法不会更小。

## 题意解释

把管材想成一排已经排好顺序的小节，每节上写着一个正整数，表示这一节的价值。你要在小节之间切三刀，把整排分给四个工班。

- m：管材一共有多少节。后面的 Python 代码把同一个数量叫 n。
- vᵢ：从左到右第 i 节的价值；是价值，不是切口编号或每段的长度。
- 连续：一段必须是原数组中挨在一起的一串数，不能抽走中间的数重新组合。
- 非空：每段至少有一节，不能有工班拿到空段。
- 段的价值：把这段包含的所有数字加起来。

题目希望四段“价值”尽量均衡，不是每段“节数”一样多。对一种切法，先算出四个段和，再用其中的最大值减最小值；在所有切法中找到最小的这个差。

比如样例 1 可以这样切：

```text
[4] | [5] | [1,2] | [8]
 4     5      3      8       ← 四段的价值
```

这次的差是 8−3=5。这里第三段有两节，其他段只有一节，这是允许的。5 不是原数组最大数减最小数得到的 8−1=7，而是**四个段和**的最大值减最小值。

所有节都要用且只能用一次。不能先排序，也不能把 4 和 8 随意放到一段里。

## 输入解释

第一行只有一个数 m，表示有多少节；第二行有 m 个正整数，依次表示从左到右各节的价值。

把样例 1 逐项拆开：

```text
5          → 一共有 5 节
4 5 1 2 8  → 第 1 节价值 4，第 2 节价值 5，第 3 节价值 1，
             第 4 节价值 2，第 5 节价值 8
```

输入中的顺序就是管材的实际顺序，不能改变。三刀的位置并没有在输入中给出，需要由你的程序寻找。

题目始终要求切成四段，不需要另外读取“4”；也没有测试组数 T，第一行的 5 不是五组测试。

Python 可以用 `n = int(input())` 读取节数，再读入 values。代码中的 n 对应题面的 m。`values[0]` 对应题面从左到右的第 1 节。

## 输出解释

只输出一个整数：所有合法切法里，“最大段和减最小段和”的最小值。不输出三个切口，也不输出四个段和。

样例 1 的 [4]、[5]、[1,2]、[8] 对应段和 4、5、3、8，极差为 5，其他切法无法更小，所以打印 `5`。

样例 2 只有四节，只能每段一节。段和都是 1，差为 0，打印 `0`。0 就是可能的最小答案，因为最大值不可能小于最小值。

样例 3 的 [9]、[1]、[1]、[1,1] 对应段和 9、1、1、2，差为 8，打印 `8`。

**这道题不需要取模。**要输出实际的最小差值，不能沿用第一题的 998244353。

## 范围解释

- **4 ≤ m ≤ 100000**：最少 4 节，最多 10 万节。至少要有 4 节，才能切出四个非空区间；m=4 时只有一种切法。
- **1 ≤ vᵢ ≤ 1000000000**：每一节的价值是 1 到 10 亿之间的整数，没有 0，也没有负数。数字可重复，也不保证有序。
- **正数为什么重要**：多纳入一节，区间和就一定增加，所以前缀和严格递增，后面才可以用只向右移动的指针找均分位置。允许负数时不能直接套这套证明。
- **数据量为什么排除暴力**：从 m−1 个缝隙里选三个切口，直接枚举需要 O(m³) 种组合；反复两重扫描的 O(m²) 在 10 万规模下也很大。本文用 O(m) 做法。
- **单个数最多 10 亿，但加起来可能更大**：10 万个 10 亿的总和是 10^14。前缀和需要存下总和，C++ 应用 64 位整数 long long；Python 的 int 会自动处理大整数。
- **答案不会是负数**：它是最大段和减最小段和。四段和完全相等时答案为 0。

这些范围是程序可以依赖的题目条件，也说明了为什么需要前缀和以及比暴力枚举更快的算法。

## 先把一刀的位置说清楚

切口位置 t 表示“前面已经有 t 个数”。例如在 [4,5,1,2,8] 中，t=2 就是切在 5 后面。

把三刀叫 left、middle、right，必须满足：

```text
1 ≤ left < middle < right ≤ n-1
```

这样四段才能都非空。注意这里的切口是“前面有几个数”，并不是说要删掉哪个数组元素。

三重循环枚举所有切口，需要 O(n³) 种组合。我们先只枚举**中间那一刀**。

## 固定中间一刀，问题拆成左右两边

还是 [4,5,1,2,8]。固定 middle=2：

```text
左边 [4,5]          右边 [1,2,8]
```

左边还要切一刀，右边也要切一刀。左边只能得到 4 和 5。右边有两种：

- [1] 与 [2,8]，和为 1、10，四段和变成 4、5、1、10，差为 9。
- [1,2] 与 [8]，和为 3、8，四段和变成 4、5、3、8，差为 5。

右侧的两段越均衡，这一次的整体极差就越小或保持不变。左侧也同理。

## 为什么左右可以各自尽量均分

固定一侧总和 T。分成 x 和 T-x，两个数的中点始终是 T/2。

两段越均衡，它们中较大的那个越小，较小的那个越大。也就是说，这一侧两个段和形成的区间在收缩。

四个段和的最大值，是左右两个最大值中较大的那个；最小值，是左右两个最小值中较小的那个。任一侧收缩，都不可能使全局最大值变大，也不可能使全局最小值变小。因此整体“最大值-最小值”不会变差。

所以：**对每一个 middle，分别找到左右最均衡的切法，就能得到这个 middle 下的最优答案。再枚举所有 middle，取最小值。**

这也解释了为什么不能只盯着总和的四分之一直接贪心切三刀：可切的位置离散，而且每段必须连续。

## 前缀和：快速算一段的总和

定义 prefix[t] 为前 t 个数的和，prefix[0]=0。

```text
values = [4, 5, 1, 2, 8]
prefix = [0, 4, 9,10,12,20]
```

例如第 3、4 个数，也就是 [1,2] 的和，为 prefix[4]-prefix[2]=12-9=3。

四段和就能写成：

```text
first  = prefix[left]
second = prefix[middle] - prefix[left]
third  = prefix[right]  - prefix[middle]
fourth = prefix[n]      - prefix[right]
```

有了 prefix，每次算四段和只需 O(1)，不必反复对切片调用 sum。

## 先理解指针为什么要移动

左边两段差的绝对值是：

```text
abs(first - second)
= abs(prefix[left] - (prefix[middle] - prefix[left]))
= abs(2 * prefix[left] - prefix[middle])
```

如果把 left 往右挪一格，这个差变小或相等，就挪；如果变大，就停。右侧的公式类似：

```text
abs(third - fourth)
= abs(2 * prefix[right] - prefix[middle] - prefix[n])
```

为什么看到下一格变差就能停？因为所有元素都是正数，prefix 严格递增。随着切口右移，差先趋近 0，再远离 0，绝对值会先下降、再上升。不会“下一格更差、再下一格又突然更好”。

两格一样好时，代码选择右边那格，便于统一维持指针只右移。

## 为什么 middle 变了，左右指针不用重来

middle 往右移动，左边的均分目标 prefix[middle]/2 也往右移动。右边的目标是 (prefix[middle]+prefix[n])/2，也单调增加。

因此 left、right 的最优位置都不用往回走。它们各自最多移动 n 次。right 还必须至少为 middle+1，才能保证第三段非空。

中间切口取 range(2,n-1)，也就是 2 到 n-2：左边至少两个数，右边至少两个数。

## 完整 Python 程序

```python
"""滴滴 2026-09-06：管材四切。前缀和 + 枚举中间切口 + 双指针。"""
import sys


def min_range(values):
    n = len(values)
    # prefix[t] 是前 t 个数的和；prefix[0] = 0。
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + values[i]

    left = 1
    right = 3
    answer = float('inf')

    # 三个切口满足 1 <= left < middle < right <= n-1。
    for middle in range(2, n - 1):
        # 左半边总和固定，让前两段的差尽量小。
        while left + 1 < middle:
            current_gap = abs(2 * prefix[left] - prefix[middle])
            next_gap = abs(2 * prefix[left + 1] - prefix[middle])
            if next_gap > current_gap:
                break
            left += 1

        # 中间切口右移后，第三段仍必须至少有一个数。
        right = max(right, middle + 1)
        while right + 1 < n:
            current_gap = abs(2 * prefix[right] - prefix[middle] - prefix[n])
            next_gap = abs(2 * prefix[right + 1] - prefix[middle] - prefix[n])
            if next_gap > current_gap:
                break
            right += 1

        first = prefix[left]
        second = prefix[middle] - prefix[left]
        third = prefix[right] - prefix[middle]
        fourth = prefix[n] - prefix[right]
        largest = max(first, second, third, fourth)
        smallest = min(first, second, third, fourth)
        answer = min(answer, largest - smallest)

    return answer


def solve():
    input = sys.stdin.readline
    n = int(input())
    values = list(map(int, sys.stdin.read().split()))
    print(min_range(values))


if __name__ == '__main__':
    solve()
```

## 对照代码读一轮

对 [4,5,1,2,8]：

1. middle=2：left=1；right 从 3 移到 4，因为右侧两段从 1、10 变成 3、8，更均衡。四段和 4、5、3、8，当前答案 5。
2. middle=3：left=1 比 left=2 更好，分别对应左侧的 4、6 和 9、1；right=4。四段和 4、6、2、8，差为 6。
3. 两次答案取最小值，得到 5。

代码里有 for 和两个 while，但指针从不后退，三个指针总共只移动 O(n) 次。因此总时间 O(n)，前缀和空间 O(n)。

## 容易写错的地方

- 切口必须严格递增：left+1<middle、right+1<n 才能继续右移。
- middle 变化后执行 right=max(right,middle+1)，避免第三段为空。
- 原数组不能排序，保持连续区间的顺序。
- 不能每个 middle 都把两个指针从头扫描，否则可能 O(n²)。
- 正数条件是“绝对差先下降后上升”和“指针不回退”的前提；有负数时这套证明失效。
- 不需要除以 2；乘 2 后比较，避免浮点数误差。
- answer 更新的是四个段和的极差，不是左右两个差的和。
